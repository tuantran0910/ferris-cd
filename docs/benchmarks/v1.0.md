## 1. Purpose & Benchmark Architecture

This benchmark validates FerrisCD's core runtime guarantees at `v1.0` scale:

1. **Cold convergence throughput:** Time for `ferriscd-controller` to clone, sanitize, render, dry-run diff, Server-Side Apply, and health-verify **50 `Application` CRs totaling 500 Kubernetes resources** from cold start until all 50 report `Synced` + `Healthy`.
2. **Steady-state reconcile latency (`p50` / `p95`):** Measured strictly over the post-convergence soak window (delta of Prometheus histogram buckets on `/metrics`) so cold-start outliers do not distort steady-state performance.
3. **Bounded memory & resource hygiene (30-minute soak):** Periodic sampling of controller RSS (KiB/MiB) and open file descriptors (FDs) across a 30-minute steady-state soak (`requeueAfterSeconds: 30`, ~3,000 steady-state reconciles across 50 apps) to confirm a flat post-warmup RSS curve, zero leaked FDs/sockets, zero controller restarts, and zero panics.

### Why Memory Stays Bounded in This Benchmark

- **Steady-state working set:** 50 `Application`s sharing 1 monorepo at 1 commit occupy **1** `RepoCache` entry (`1 <= 64`) and **50** `RenderCache` entries (`50 <= 128`, keyed by `(repo_url, commit_sha, source_path, app_namespace, app_name, destination_namespace, cluster_kube_version, canonical_renderer_config)`). After cold convergence, steady-state reconciles hit `RenderCache` without re-parsing YAML or re-invoking renderers.
- **High-churn protection:** Under continuous commit churn (>64 commits or >128 render tuples), both `RepoCache` and `RenderCache` deterministically evict the least-recently-used entries instead of growing unboundedly.

## 3. Prometheus Metrics & PromQL Queries

Verified from [`crates/ferriscd-controller/src/metrics.rs`](../../crates/ferriscd-controller/src/metrics.rs). Exposed on dedicated listener `--metrics-addr` / `FERRISCD_METRICS_ADDR` (default `0.0.0.0:9090`, path `/metrics`, Prometheus text `0.0.4`):

| Metric Family | Type | Labels | Notes |
|---|---|---|---|
| `ferriscd_reconcile_duration_seconds` | Histogram | `result` (`success`, `retryable`, `terminal`) | 14 exponential buckets: `0.005 * 2^k` (`0.005`s .. `40.96`s) + `+Inf` |
| `ferriscd_reconcile_total` | Counter | `result` (`success`, `retryable`, `terminal`) | Monotonic completed reconciles |
| `ferriscd_app_sync_status` | Gauge | `app_namespace`, `app_name`, `status` (`Synced`, `OutOfSync`, `Unknown`) | `1` for current status, `0` for others; removed on CR deletion |
| `ferriscd_app_health_status` | Gauge | `app_namespace`, `app_name`, `status` (`Healthy`, `Progressing`, `Degraded`, `Suspended`, `Missing`, `Unknown`) | `1` for current status, `0` for others; removed on CR deletion |
| `ferriscd_git_fetch_duration_seconds` | Histogram | *(none)* | Same 14 exponential buckets (`0.005`s .. `40.96`s, `+Inf`) |
| `ferriscd_render_cache_total` | Counter | `outcome` (`hit`, `miss`) | Bridged from `RenderCache::stats()` |
| `ferriscd_active_reconciles` | Gauge | *(none)* | In-flight reconciles (bounded by `DEFAULT_CONCURRENCY = 8` per scope) |

### Reference PromQL Queries

```promql
# Steady-state p50 reconcile latency (successful passes, 5m rolling window)
histogram_quantile(
  0.50,
  sum by (le) (rate(ferriscd_reconcile_duration_seconds_bucket{result="success"}[5m]))
)

# Steady-state p95 reconcile latency (successful passes, 5m rolling window)
histogram_quantile(
  0.95,
  sum by (le) (rate(ferriscd_reconcile_duration_seconds_bucket{result="success"}[5m]))
)

# Git resolve/checkout p95 latency
histogram_quantile(
  0.95,
  sum by (le) (rate(ferriscd_git_fetch_duration_seconds_bucket[5m]))
)

# RenderCache hit ratio (%)
100 * (
  rate(ferriscd_render_cache_total{outcome="hit"}[5m])
  /
  clamp_min(sum(rate(ferriscd_render_cache_total[5m])), 1e-9)
)

# Applications currently Synced and Healthy
sum(ferriscd_app_sync_status{status="Synced"})
sum(ferriscd_app_health_status{status="Healthy"})

# Retryable / terminal reconcile errors over soak window
increase(ferriscd_reconcile_total{result=~"retryable|terminal"}[30m])
```

### B. Live 30-Minute `kind` Scale & Memory Soak Run

```bash
# 1. Create a fresh local kind cluster and verify context starts with `kind-`
kind create cluster --name ferriscd-bench
kubectl config current-context   # MUST print `kind-ferriscd-bench`

# 2. Install FerrisCD CRDs (`applications.ferriscd.io` & `appprojects.ferriscd.io`) and create the control-plane namespace
cargo build --release --bin ferriscd
# Optional: regenerate manifests first with `./target/release/ferriscd crd generate`
kubectl apply -f deploy/crds/
kubectl create namespace ferriscd-system

# 3. Start the controller in release mode with local repo support and dedicated /metrics listener
./target/release/ferriscd controller \
  --namespace ferriscd-system \
  --allow-local-repos \
  --metrics-addr 127.0.0.1:9090 &
CONTROLLER_PID=$!

# 4. Run the 50-app / 500-resource / 30-minute soak benchmark (applies AppProject `bench-scale`
#    before the 50 Application CRs and saves raw CSV/Prometheus artifacts)
./benchmarks/scale_harness.sh \
  --apps 50 \
  --resources-per-app 10 \
  --soak-minutes 30 \
  --warmup-minutes 5 \
  --sample-interval 30 \
  --requeue-seconds 30 \
  --controller-pid "${CONTROLLER_PID}" \
  --metrics-url http://127.0.0.1:9090/metrics \
  --results-dir ./benchmark-results-v1.0

# 5. Clean up benchmark Application CRs, AppProject `bench-scale`, and all 50 destination namespaces
./benchmarks/scale_harness.sh --cleanup

# 6. Stop controller and optionally delete the kind cluster
kill -TERM "${CONTROLLER_PID}"
kind delete cluster --name ferriscd-bench
```

> **In-cluster controller mode:** Omit `--controller-pid` and pass `--controller-selector app.kubernetes.io/name=ferriscd-controller` (plus `--repo-url <in-cluster-git-http-url>` and a `kubectl port-forward` to `:9090`) when benchmarking the hardened container image deployed via Helm.
