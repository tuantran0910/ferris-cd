## Pass 2: Adversarial Review of Plan v1.0 + User Design Alignment -> Plan v2.0

An independent adversarial review pass audited `MASTER_PLAN.md` v1.0 and `ROADMAP.md` v1.0 against live 2026 Rust/Kubernetes crate behavior, uncovering **9 Critical, 9 High, and 6 Medium** traps—all resolved in v2.0 alongside 5 explicit user design choices.

### User Design Decisions Locked In
1. **Application Namespace Scope:** Control-plane namespace (`ferriscd-system`) through `v0.4`, adding opt-in Apps-in-any-namespace (`AppProject.spec.sourceNamespaces`) + mandatory `ServiceAccount` impersonation in Phase 12 (ADR-007, `T12.2`).
2. **Drift Detection Model:** On-demand live fetch on requeue/webhook (low RAM, least-privilege RBAC), with opt-in hashed label-scoped watches documented for post-`v1.0` (ADR-004, `T16.8`).
3. **SSH & Container Image:** Minimal Wolfi / Debian-slim container bundling `openssh-client` + `ca-certificates` (non-root, read-only rootfs, `/tmp` `emptyDir`) so `gix` supports both HTTPS and SSH cleanly (ADR-005, `T02.4`, `T16.5`).
4. **Frontend Stack:** Modern TypeScript Web UI (**React 19 + TypeScript + Vite + Tailwind CSS + TanStack Query + React Flow**) consuming an OpenAPI 3.1 schema generated by `ferriscd-server` via `utoipa` (ADR-008, `T14.1`, `T16.1`–`T16.4`).
5. **Knowledge Base Cadence:** One focused lesson + hands-on `kind` experiment per Phase (16 lessons total) alongside concise ADRs.
